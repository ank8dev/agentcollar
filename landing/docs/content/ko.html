AgentCollar는 내 컴퓨터에서 실행되는 작은 브로커입니다. AI 에이전트는 한 가지 작업을 위한 짧은 통행증을 브로커에게 요청합니다. 나는 그것을 Telegram에서 승인합니다. 에이전트는 내 비밀번호를 절대 보지 못합니다.

이 페이지의 모든 기능은 동작하며 처음부터 끝까지 테스트했습니다. Claude Code가 mandate를 요청하고, 여러분이 Telegram에서 승인하면, 실제 Gmail을 읽고 초안을 남깁니다. 하지만 개발은 중단된 상태이며, 작성자가 다시 돌아오지 않을 수도 있습니다. 새 기능도, 약속된 수정도 없습니다. 코드는 MIT 라이선스로 계속 공개되어 있으니 필요하면 fork하세요. 취미 프로젝트입니다. 본인 책임으로 사용하고, 잃어서는 안 되는 계정은 연결하지 마세요.

Telegram에서 승인

{{telegram}}

Claude Code에서 쓰기

MCP(Model Context Protocol)는 AI 에이전트와 도구 사이의 공통 언어입니다. AgentCollar가 이 언어를 쓰기 때문에, Claude Code는 브로커를 스스로 사용할 수 있습니다. 명령어 하나로 추가합니다:

{{mcp-add}}

agcl server를 다른 터미널에서 계속 실행해 두세요. 그런 다음 Claude에게 이렇게만 부탁하면 됩니다:

{{mcp-prompt}}

그다음 일어나는 일:

  1. Claude가 필요한 작업을 담아 request_mandate를 호출합니다.
  2. 휴대폰이 울립니다. ✅ Approve를 누릅니다.
  3. Claude가 mandate_status를 호출해 approved를 확인하고, 이어서 gmail_read_inbox와 gmail_create_draft를 호출합니다.
  4. 허락 없이 gmail_send를 시도하면 브로커가 거부합니다.

짧은 수명

맨데이트는 스스로 만료됩니다. 답이 없는 요청은 10분 뒤에 사라집니다.

작업 하나만

목록에 있는 작업만. 임시 보관 메일이 발송으로 바뀌지 않습니다.

언제든 취소

Telegram에서 한 번 탭하거나 agcl revoke. 다음 요청부터 적용됩니다.

모두 기록

모든 검사, 모든 결정을 한 줄씩. 토큰은 절대 기록하지 않습니다.

브로커가 막아 주는 것

  • 도난당한 맨데이트 토큰: 작업 하나, 짧은 시간, 취소 가능. 메일함 전체를 영원히 내주는 것이 아닙니다.
  • 폭주하는 에이전트: 한도가 멈추고, 로그가 언제 시작됐는지 보여 줍니다.
  • 메일 속 프롬프트 인젝션: 에이전트가 믿을 수는 있어도 그 작업은 맨데이트에 없고, MCP를 통하면 토큰은 보이지도 않습니다.
  • 가짜 승인 메시지: 작업은 반드시 app.verb 형식이어야 하고, 에이전트의 글은 정리된 한 줄로 맨 마지막에 표시됩니다.
  • 스스로를 승인하는 에이전트: 승인은 HTTP나 파일로는 절대 할 수 없습니다. Telegram(내 id)이나 브로커 자체의 터미널에서만 가능합니다.
  • localhost를 공격하는 웹 페이지: 브라우저 요청은 거부됩니다.
  • 내 이름으로 보내기: Gmail 연결에는 읽기와 임시 보관 권한만 있습니다. 브로커에 실수가 있어도 메일을 보낼 수 없습니다.
  • 변조된 npm 패키지: 릴리스는 provenance(검증 가능한 출처)와 함께 배포됩니다. npm audit signatures로 확인하세요.

(아직) 막지 못하는 것

  • 이미 내 사용자 권한으로 실행 중인 악성 코드는 ~/.agentcollar/를 읽을 수 있습니다.
  • 브로커가 멈추면 맨데이트가 사라집니다.

문제 해결

Telegram에 아무것도 오지 않아요

봇을 열고 Start를 적어도 한 번 누르세요. 봇은 먼저 말을 걸 수 없습니다. agcl server에 Approvals: Telegram이 보이는지 확인하세요. this terminal이라고 나오면 agcl setup을 실행하세요.

설정 중 "Another program is already listening to this bot"이 나와요

(다른 프로그램이 이미 이 봇을 듣고 있습니다.) 대개 내 agcl server입니다. Ctrl+C로 멈추고 agcl setup을 다시 실행하세요.

에이전트가 브로커가 실행 중이 아니라고 해요

별도의 터미널 탭에서 broker를 시작하고 그 탭을 열어 두세요: agcl server (또는 그냥 agcl). broker와 에이전트는 같은 컴퓨터에서 실행되어야 합니다. 그런 다음 에이전트에게 다시 시도하라고 하세요.

agcl mandates가 "The broker is not running"이라고 해요

맨데이트는 브로커의 메모리에 있으므로, 멈춘 뒤에는 보여 줄 것이 없습니다. 시작한 뒤 에이전트가 다시 요청하게 하세요.

일주일 뒤 Gmail이 작동하지 않아요

Google 앱이 테스트 모드여서 Google이 로그인을 끝냈습니다. agcl gmail connect를 다시 실행하세요.

Google이 “Access blocked: … has not completed the Google verification process” (Error 403: access_denied)라고 표시합니다

Google 앱이 테스트 모드라서 Google은 테스트 사용자만 들여보냅니다. Google Cloud에서 Google Auth Platform → Audience → Test users를 열어 Gmail 주소를 추가한 뒤 agcl gmail connect를 다시 실행하세요. 앱을 게시하지 마세요.

agcl: command not found

짧은 이름을 쓰려면 설치가 필요합니다: npm install -g agentcollar. 설치하지 않으려면 npx agentcollar를 쓰세요.

8787 포트가 이미 사용 중이에요

다른 브로커가 이미 실행 중일 수 있습니다(agcl mandates로 확인). 아니면 다른 포트로 시작하세요: BROKER_PORT=8788 agcl server. 그리고 새 주소를 에이전트에게 알려 주세요.

시작할 때 "Unsupported engine"이나 문법 오류가 나요

Node.js가 너무 오래되었습니다. AgentCollar에는 22 이상이 필요합니다: node --version.
