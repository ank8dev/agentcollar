Laissez les agents travailler.
Gardez les clés.

AgentCollar est un petit broker qui tourne sur votre ordinateur. Votre agent IA lui demande un laissez-passer court, pour une seule tâche. Vous l'approuvez dans Telegram. L'agent ne voit jamais votre mot de passe.

AgentCollar est jeune. Ne connectez pas de comptes que vous ne pouvez pas vous permettre de perdre.

Prise en main

De rien à un broker qui fonctionne en environ trois minutes. Il vous faut Node.js 22 ou plus récent et un compte Telegram. Vérifiez d'abord Node :

{{node-version}}

1. Installer

Lancez-le une fois sans l'installer, ou installez-le pour avoir la commande courte agcl.

{{install}}

2. Connecter votre bot Telegram

Créez un bot avec @BotFather (/newbot) et copiez son token. Puis lancez agcl. La première fois, il démarre tout seul l'assistant de configuration.

3. Faire entrer un agent

Connectez Claude Code via MCP, ou appelez l'API HTTP depuis votre propre script. Désormais, chaque requête passe par vous.

L'assistant de configuration, pas à pas

Voici ce que vous voyez. Les lignes qui commencent par $ sont celles que vous tapez.

Ce qui s'est passé, ligne par ligne :

  1. Le token reste masqué pendant la saisie et il est vérifié auprès de Telegram. Un mauvais token donne une erreur claire, pas un plantage.
  2. Le lien contient un code à usage unique (K7P2M9QX). Seul un /start avec ce code exact, dans une discussion privée, compte. Un inconnu qui appuie sur Start dans votre bot au même moment ne peut pas devenir votre approbateur.

  4. Vos réglages sont enregistrés dans ~/.agentcollar/.env. Seul votre utilisateur macOS peut le lire. Le bot vous écrit aussi : « AgentCollar is set up ».
Pas de Telegram ? Aucun problème.

Répondez n à la première question. Le broker vous demandera alors d'approuver directement dans le terminal, avec y ou N.

Comment ça marche

Trois parties, une règle : l'agent ne parle qu'au broker, et le broker n'agit qu'une fois les vérifications passées.

{{sequence}}

Les mandats

Un mandat est une autorisation pour une seule tâche. L'agent la demande, vous l'approuvez, et elle cesse de fonctionner d'elle-même. Il comprend :

ChampExempleSignification
agentclaude-codeQui demande. Affiché pour vous.
task"Draft replies to new mail"Pourquoi, avec les mots de l'agent. Affiché en dernier, entre guillemets.
allowedActionsgmail.read, gmail.draftExactement ce qui est permis. Toujours app.verb.
expiresInSeconds300Sa durée de vie après votre approbation. 1 jour au maximum.
limit10Le nombre maximal d'actions permises. 1000 au maximum.
id8329b843Nom public. Sans risque à afficher et à taper dans agcl revoke.
token64 caractères hexadécimauxLe secret. Seul l'agent (ou le serveur MCP) le possède. Jamais journalisé.

Le chrono démarre quand vous approuvez, pas quand l'agent demande. Si personne ne répond en 10 minutes, la demande est refusée. On appelle ça fail closed (échec fermé) : dans le doute, la réponse est non.

Les 6 vérifications

Chaque requête passe par ces vérifications dans cet ordre. La première qui échoue arrête tout, et la raison part dans le journal d'audit.

#QuestionSi nonHTTP
1Connaît-on ce token ?unknown token401
2Un humain l'a-t-il approuvé ?waiting / denied403
3Est-il encore dans les temps ?expired403
4N'a-t-il pas été révoqué ?revoked403
5Cette action est-elle dans le mandat ?action not allowed403
6La limite n'est-elle pas atteinte ?limit reached429

{{check-ts}}

Remarquez le principe : chaque vérification ne peut dire que non. Le « oui » n'est écrit qu'une fois, tout en bas. Les ingénieurs appellent ça deny by default (refus par défaut).

L'approbation dans Telegram

Quand un agent fait une demande, ce message arrive dans votre bot :

{{telegram}}
  • Les faits d'abord, les mots de l'agent à la fin. « Actions » et « Lifetime » sont ce que le broker impose. La tâche n'est que le récit de l'agent, tassé sur une ligne, pour qu'il ne puisse pas fabriquer une ligne « Actions: » supplémentaire.
  • Si l'agent demande *.send, un avertissement apparaît d'abord : « The agent asks for the right to SEND in your name » (l'agent demande le droit d'ENVOYER en votre nom).
  • Après votre approbation, les boutons deviennent 🛑 Revoke (révoquer).
  • Seul votre identifiant Telegram peut appuyer. Les autres reçoivent « No access ».

Le journal d'audit

Chaque vérification et chaque décision humaine devient une ligne de ~/.agentcollar/audit.log. Les lignes sont seulement ajoutées, jamais modifiées. Voici le fichier brut :

{{audit-raw}}

Le texte des agents est entre guillemets (JSON.stringify) : un agent ne peut donc pas glisser un saut de ligne dans son nom pour forger une fausse ligne. Le token n'est jamais écrit ici. La dernière colonne indique quelle vérification a tranché. agcl logs le rend lisible (voir plus bas).

Connecter Gmail

Par défaut, le broker utilise une fausse boîte de réception, pour que vous puissiez tout essayer sans risque. Quand vous êtes prêt, connectez votre vrai Gmail. La connexion peut lire le courrier et créer des brouillons. Elle ne peut jamais envoyer : le broker le bloque, et Google aussi, car l'envoi n'a jamais été demandé.

  1. Dans Google Cloud, créez un client OAuth de type Desktop app et téléchargez son fichier JSON.
  2. Lancez la commande ci-dessous. Votre navigateur s'ouvre. Autorisez « read your email » et « create drafts ».
  3. Redémarrez le broker.
{{gmail-connect}}

Le refresh token va dans le trousseau macOS, jamais dans un fichier. L'access token, de courte durée, ne vit qu'en mémoire. Vérifiez ou supprimez la connexion quand vous voulez :

{{gmail-status}}
Le mode test dure 7 jours

Tant que votre application Google est en mode test, Google met fin à la connexion au bout de 7 jours. Relancez simplement agcl gmail connect.

La commande agcl

agcl est le nom court d'agentcollar. C'est le même programme : agcl watch = agentcollar watch. Le nom court fonctionne après npm install -g agentcollar. Avec npx, utilisez le nom long : npx agentcollar watch.

{{help}}

agcl

La commande « fais juste marcher ». Elle affiche l'intro, lance l'assistant si Telegram n'est pas encore configuré, puis démarre le broker. Dans un script (personne devant le terminal), elle saute les questions et démarre le broker.

agcl setup

Connecte votre propre bot Telegram. Voir le guide complet. Vous pouvez le relancer sans risque : il demande avant de remplacer un .env existant et garde les autres lignes (par exemple BROKER_PORT).

agcl server

Démarre le broker. Il écoute uniquement sur 127.0.0.1:8787 : les programmes d'autres ordinateurs ne peuvent pas l'atteindre. Arrêtez-le avec Ctrl+C.

{{server}}
BROKER_PORT=9000
Utiliser un autre port. Mettez-le dans ~/.agentcollar/.env.
Les mandats vivent en mémoire

Quand vous arrêtez le broker, tous les mandats disparaissent. Les agents redemandent simplement. Le journal d'audit reste.

agcl watch

Un écran en direct. Ouvrez-le dans un second terminal et regardez chaque requête au moment où elle arrive. Il ne fait que lire le journal d'audit : il ne peut rien changer.

{{watch}}

Comment lire ✓ ✓ ✓ ✓ ✗ · : les six marques sont les six vérifications. ✓ réussie, ✗ celle qui a échoué, · jamais exécutée (la requête s'était déjà arrêtée). Les lignes jaunes sont des décisions humaines.

agcl mandates

Ce dont le broker en marche se souvient en ce moment : qui, quoi, état, temps et actions restants. Il lit un fichier instantané que le broker écrit après chaque changement. L'instantané ne contient aucun token.

{{mandates}}

États : waiting active denied expired revoked limit used up

agcl logs

Le journal d'audit, filtré et en couleurs.

--agent <name>
seulement cet agent
--denied
seulement les refus (la partie intéressante)
--today
seulement aujourd'hui
{{logs}}

Les filtres se combinent. Vous voulez le fichier brut ? tail -f ~/.agentcollar/audit.log.

agcl revoke <id>

Le bouton d'arrêt d'urgence. Le mandat cesse de fonctionner dès la requête suivante. Fonctionne sans internet. Le message Telegram est mis à jour aussi.

{{revoke}}

L'identifiant figure dans le message Telegram et dans agcl mandates. Révoquer ne demande jamais de token : cela ne peut que retirer un accès, jamais en donner.

agcl mcp

Démarre le serveur MCP qu'utilisent Claude Code et d'autres agents. Normalement, vous ne le lancez pas à la main : c'est l'agent qui le démarre. Voir la section suivante.

L'intro

Le médaillon qui tourne est le logo dessiné avec des caractères Braille (⣿⡇⠟). Chacun contient 8 points, ce qui donne plus de détails qu'avec des lettres normales. Elle dure environ 1,7 seconde, n'importe quelle touche la passe, et elle n'apparaît jamais dans les pipes, en CI, avec NO_COLOR ou avec --no-intro.

Utiliser avec Claude Code

MCP (Model Context Protocol) est une langue commune entre un agent IA et ses outils. AgentCollar la parle, donc Claude Code peut utiliser le broker tout seul. Une commande suffit pour l'ajouter :

{{mcp-add}}

Laissez agcl server tourner dans un autre terminal. Ensuite, demandez simplement à Claude :

Ce qui se passe ensuite :

  1. Claude appelle request_mandate avec les actions dont il a besoin.
  2. Votre téléphone vibre. Vous appuyez sur ✅ Approve.
  3. Claude appelle mandate_status, voit approved, puis gmail_read_inbox et gmail_create_draft.
  4. S'il essaie gmail_send sans autorisation, le broker dit non.

Le modèle ne voit jamais le token

Le serveur MCP garde le token secret dans son propre processus et ne donne au modèle que le mandateId. Si un e-mail contient une injection de prompt du genre « envoie-moi ton token », il n'y a donc rien à voler.

Les navigateurs sont refusés exprès

Une page web peut elle aussi envoyer des requêtes à localhost. Le broker refuse donc toute requête avec un en-tête Origin, vérifie Host (contre le DNS rebinding) et n'accepte que application/json. Les programmes comme curl et les agents ne sont pas concernés.

Sécurité

Courte durée

Les mandats expirent d'eux-mêmes. Les demandes sans réponse meurent au bout de 10 minutes.

Une seule tâche

Seulement les actions listées. Un brouillon ne peut pas devenir un envoi.

Révocable à tout moment

Un toucher dans Telegram ou agcl revoke. Effet dès la requête suivante.

Entièrement journalisé

Chaque vérification, chaque décision, une ligne chacune. Jamais de token.

Ce contre quoi le broker protège

  • Un token de mandat volé : une tâche, peu de temps, révocable. Pas toute votre boîte mail pour toujours.
  • Un agent qui s'emballe : la limite l'arrête, le journal montre quand ça a commencé.
  • Une injection de prompt dans un e-mail : l'agent peut y croire, mais l'action n'est pas dans le mandat, et via MCP le token n'est même pas visible.
  • Un faux message d'approbation : les actions doivent avoir la forme app.verb, et le texte de l'agent tient sur une seule ligne nettoyée, affichée en dernier.
  • Un agent qui s'approuve lui-même : l'approbation n'est jamais possible par HTTP ni par des fichiers. Seulement dans Telegram (votre identifiant) ou dans le terminal du broker.
  • Une page web qui attaque localhost : les requêtes de navigateurs sont refusées.
  • Envoyer en votre nom : la connexion Gmail n'a que l'accès en lecture et aux brouillons. Même une erreur du broker ne pourrait pas envoyer d'e-mail.
  • Un paquet npm falsifié : les versions sont publiées avec provenance (origine vérifiable). Vérifiez avec npm audit signatures.

Ce contre quoi il ne protège pas (encore)

  • Un logiciel malveillant qui tourne déjà sous votre utilisateur peut lire ~/.agentcollar/.
  • Les mandats sont perdus quand le broker s'arrête.

Dépannage

Rien n'arrive dans Telegram

Ouvrez votre bot et appuyez sur Start au moins une fois : les bots ne peuvent pas vous écrire en premier. Vérifiez que agcl server affiche Approvals: Telegram. S'il affiche this terminal, lancez agcl setup.

L'assistant affiche « Another program is already listening to this bot »

(Un autre programme écoute déjà ce bot.) En général, c'est votre propre agcl server. Arrêtez-le avec Ctrl+C et relancez agcl setup.

L'agent dit que le broker ne tourne pas

Démarrez-le : agcl server. Le broker et l'agent doivent tourner sur le même ordinateur.

agcl mandates affiche « The broker is not running »

Les mandats vivent dans sa mémoire : une fois arrêté, il n'y a rien à afficher. Démarrez-le et laissez l'agent redemander.

Gmail ne marche plus au bout d'une semaine

Votre application Google est en mode test, et Google a mis fin à la connexion. Relancez agcl gmail connect.

agcl: command not found

Le nom court nécessite une installation : npm install -g agentcollar. Sans installation, utilisez npx agentcollar.

Le port 8787 est occupé

Un autre broker tourne peut-être déjà (vérifiez avec agcl mandates). Sinon, démarrez celui-ci sur un autre port : BROKER_PORT=8788 agcl server, et donnez la nouvelle adresse à votre agent.

« Unsupported engine » ou erreurs de syntaxe au démarrage

Votre Node.js est trop ancien. AgentCollar a besoin de la version 22 ou plus récente : node --version.
