Claude Code के साथ इस्तेमाल

MCP (Model Context Protocol) AI एजेंट और उसके टूल्स के बीच की साझा भाषा है। AgentCollar यह भाषा बोलता है, इसलिए Claude Code ब्रोकर को ख़ुद इस्तेमाल कर सकता है। एक कमांड से इसे जोड़ें:

{{mcp-add}}

agcl server को दूसरे टर्मिनल में चलता रहने दें। फिर बस Claude से कहें:

{{mcp-prompt}}

आगे क्या होता है:

  1. Claude ज़रूरी कामों के साथ request_mandate को कॉल करता है।
  2. आपका फ़ोन बजता है। आप ✅ Approve दबाते हैं।
  3. Claude mandate_status को कॉल करता है, approved देखता है, फिर gmail_read_inbox और gmail_create_draft।
  4. अगर वह बिना अनुमति gmail_send आज़माता है, तो ब्रोकर मना कर देता है।

पूरा रिकॉर्ड

हर जाँच, हर फ़ैसला, हर एक की एक पंक्ति। टोकन कभी नहीं।

ब्रोकर किन चीज़ों से बचाता है

  • चोरी हुआ मैंडेट टोकन: एक काम, कम समय, रद्द करने योग्य। हमेशा के लिए पूरा मेलबॉक्स नहीं।
  • बेक़ाबू एजेंट: सीमा उसे रोक देती है, लॉग दिखाता है कि यह कब शुरू हुआ।
  • ईमेल में प्रॉम्प्ट इंजेक्शन: एजेंट उस पर भरोसा कर सकता है, पर वह काम मैंडेट में नहीं है, और MCP के ज़रिए तो टोकन दिखता भी नहीं।
  • नकली मंज़ूरी संदेश: कामों का रूप app.verb होना चाहिए, और एजेंट का टेक्स्ट एक साफ़ की गई पंक्ति है, सबसे आख़िर में।
  • ख़ुद को मंज़ूरी देता एजेंट: HTTP या फ़ाइलों से मंज़ूरी कभी संभव नहीं। सिर्फ़ Telegram (आपकी id) में या ब्रोकर के अपने टर्मिनल में।
  • localhost पर हमला करता वेब पेज: ब्राउज़र के अनुरोध मना कर दिए जाते हैं।
  • आपके नाम से भेजना: Gmail कनेक्शन के पास सिर्फ़ पढ़ने और ड्राफ़्ट की अनुमति है। ब्रोकर की कोई ग़लती भी ईमेल नहीं भेज सकती।
  • छेड़छाड़ किया गया npm पैकेज: रिलीज़ provenance (जाँचने योग्य स्रोत) के साथ प्रकाशित होते हैं। npm audit signatures से जाँचें।

यह (अभी) किन चीज़ों से नहीं बचाता

  • आपके यूज़र के रूप में पहले से चल रहा मैलवेयर ~/.agentcollar/ पढ़ सकता है।
  • ब्रोकर रुकने पर मैंडेट खो जाते हैं।

समस्या समाधान

Telegram में कुछ नहीं आता

अपना बॉट खोलें और कम से कम एक बार Start दबाएँ: बॉट आपको पहले संदेश नहीं भेज सकते। जाँचें कि agcl server में Approvals: Telegram दिख रहा है। अगर this terminal दिखे, तो agcl setup चलाएँ।

सेटअप कहता है "Another program is already listening to this bot"

(कोई दूसरा प्रोग्राम पहले से इस बॉट को सुन रहा है।) आम तौर पर यह आपका अपना agcl server होता है। उसे Ctrl+C से बंद करें और agcl setup फिर चलाएँ।

एजेंट कहता है कि ब्रोकर नहीं चल रहा

broker को एक अलग टर्मिनल टैब में शुरू करें और वह टैब खुला रखें: agcl server (या बस agcl)। broker और एजेंट एक ही कंप्यूटर पर चलने चाहिए। फिर एजेंट से दोबारा कोशिश करने को कहें।

agcl mandates कहता है "The broker is not running"

मैंडेट उसकी मेमोरी में रहते हैं, इसलिए बंद होने के बाद दिखाने को कुछ नहीं होता। उसे शुरू करें और एजेंट को फिर से माँगने दें।

एक हफ़्ते बाद Gmail ने काम करना बंद कर दिया

आपका Google ऐप टेस्टिंग मोड में है, और Google ने साइन-इन ख़त्म कर दिया। agcl gmail connect फिर से चलाएँ।

Google कहता है “Access blocked: … has not completed the Google verification process” (Error 403: access_denied)

आपका Google ऐप टेस्टिंग मोड में है, इसलिए Google सिर्फ़ उसके टेस्ट यूज़र्स को अंदर आने देता है। Google Cloud में Google Auth Platform → Audience → Test users खोलें, अपना Gmail पता जोड़ें, फिर agcl gmail connect दोबारा चलाएँ। ऐप को publish न करें।

agcl: command not found

छोटे नाम के लिए इंस्टॉल ज़रूरी है: npm install -g agentcollar। बिना इंस्टॉल के npx agentcollar इस्तेमाल करें।

पोर्ट 8787 व्यस्त है

शायद कोई दूसरा ब्रोकर पहले से चल रहा है (agcl mandates से जाँचें)। या इसे दूसरे पोर्ट पर शुरू करें: BROKER_PORT=8788 agcl server, और अपने एजेंट को नया पता बताएँ।

शुरू करते समय "Unsupported engine" या सिंटैक्स त्रुटियाँ

आपका Node.js बहुत पुराना है। AgentCollar को 22 या नया चाहिए: node --version।
