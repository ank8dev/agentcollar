AgentCollar is a small broker that runs on your computer. Your AI agent asks it for a short pass for one task. You approve it in Telegram. The agent never sees your password.

Get started

From nothing to a working broker in about three minutes. You need Node.js 22 or newer and a Telegram account. Check Node first:

1. Install

Run it once without installing, or install it to get the short command agcl.

2. Connect your Telegram bot

Create a bot with @BotFather (/newbot) and copy its token. Then run agcl. The first time, it starts the setup wizard by itself.

3. Let an agent in

How it works

Three parties, one rule: the agent only talks to the broker, and the broker only acts after the checks pass.

{{sequence}}

Mandates

A mandate is a permission for one task. The agent asks for it, you approve it, and it stops working by itself. It has:

FieldExampleMeaning
agentclaude-codeWho asks. Shown to you.
task"Draft replies to new mail"Why, in the agent's own words. Shown last, in quotes.
allowedActionsgmail.read, gmail.draftExactly what is allowed. Always app.verb.
expiresInSeconds300How long it lives after you approve. At most 1 day.
limit10The most allowed actions. At most 1000.
id8329b843Public name. Safe to show and to type in agcl revoke.
token64 hex charactersThe secret. Only the agent (or the MCP server) has it. Never logged.

A mandate goes through these states:

{{lifecycle}}

The clock starts when you approve, not when the agent asks. If nobody answers in 10 minutes, the request is denied. This is called fail closed: when in doubt, the answer is no.

The 6 checks

Every request goes through these checks in this order. The first one that fails stops everything, and the reason goes to the audit log.

#QuestionIf noHTTP
1Do we know this token?unknown token401
2Did a human approve it?waiting / denied403
3Is it still within its time?expired403
4Was it not revoked?revoked403
5Is this action in the mandate?action not allowed403
6Is the limit not reached?limit reached429

This is the heart of the code, broker/src/check.ts. It is short on purpose:

{{check-ts}}

Notice the pattern: every check can only say no. "Yes" is written once, at the very bottom. Engineers call this deny by default.

Approval in Telegram

When an agent asks, this message comes to your bot:

{{telegram}}
  • Facts first, the agent's words last. "Actions" and "Lifetime" are what the broker enforces. The task is only the agent's story, squashed into one line, so it cannot fake an extra "Actions:" line.
  • If the agent asks for *.send, a warning comes first: "The agent asks for the right to SEND in your name".
  • After you approve, the buttons change to 🛑 Revoke.
  • Only your Telegram user id can press. Everyone else gets "No access".

The audit log

Every check and every human decision becomes one line in ~/.agentcollar/audit.log. Lines are only added, never changed. This is the raw file:

{{audit-raw}}

Text from agents is in quotes (JSON.stringify), so an agent cannot put a line break in its name and forge a fake line. The token is never written here. The last column says which check decided. agcl logs turns it into something readable (see below).

Connect Gmail

Out of the box the broker uses a fake inbox, so you can try everything safely. When you are ready, connect your real Gmail. The connection can read mail and create drafts. It can never send: the broker blocks it, and Google blocks it too, because sending was never asked for.

  1. In Google Cloud, create an OAuth client of type Desktop app and download its JSON file.
  2. Run the command below. Your browser opens. Allow "read your email" and "create drafts".
  3. Restart the broker.
{{gmail-connect}}

The refresh token goes to the macOS Keychain, never to a file. The short-lived access token lives only in memory. Check or remove the connection at any time:

{{gmail-status}}
Testing mode lasts 7 days

While your Google app is in testing mode, Google ends the sign-in after 7 days. Just run agcl gmail connect again.

The agcl command

agcl is the short name of agentcollar. They are the same program: agcl watch = agentcollar watch. The short name works after npm install -g agentcollar. With npx, use the long name: npx agentcollar watch.

{{help}}

agcl

The "just make it work" command. Shows the intro, runs the setup wizard if Telegram is not set up yet, then starts the broker. In a script (no person at the terminal), it skips the questions and starts the broker.

agcl setup

Connects your own Telegram bot. See the full walkthrough. Safe to run again: it asks before replacing an existing .env and keeps other lines (for example BROKER_PORT).

agcl server

Starts the broker. It listens on 127.0.0.1:8787 only: programs on other computers cannot reach it. Stop it with Ctrl+C.

{{server}}
BROKER_PORT=9000
Use another port. Put it in ~/.agentcollar/.env.
Mandates live in memory

When you stop the broker, all mandates disappear. Agents simply ask again. The audit log stays.

agcl watch

A live screen. Open it in a second terminal and watch every request as it happens. It only reads the audit log: it cannot change anything.

{{watch}}

How to read ✓ ✓ ✓ ✓ ✗ ·: the six marks are the six checks. ✓ passed, ✗ is the one that failed, · never ran (the request had already stopped). Yellow lines are human decisions.

agcl mandates

What the running broker remembers right now: who, what, state, time and actions left. It reads a snapshot file that the broker writes after every change. The snapshot has no tokens.

{{mandates}}

States: waiting active denied expired revoked limit used up

agcl logs

The audit log, filtered and colored.

--agent <name>
only this agent
--denied

--today

{{logs}}

Filters combine. Want the raw file? tail -f ~/.agentcollar/audit.log.

agcl revoke <id>

The kill switch. The mandate stops working on the very next request. Works without internet. The Telegram message updates too.

{{revoke}}

The id is in the Telegram message and in agcl mandates. Revoking never needs a token: it can only take access away, never give it.

agcl mcp

Starts the MCP server that Claude Code and other agents use. You normally don't run it by hand: the agent starts it. See the next section.

The intro

The spinning medallion is the logo drawn with Braille characters (⣿⡇⠟). Each one holds 8 dots, so a picture gets more detail than with normal letters. It lasts about 1.7 seconds, any key skips it, and it never shows in pipes, CI, with NO_COLOR or with --no-intro.

Use with Claude Code

MCP (Model Context Protocol) is a common language between an AI agent and its tools. AgentCollar speaks it, so Claude Code can use the broker by itself. One command adds it:

{{mcp-add}}

Keep agcl server running in another terminal. Then just ask Claude:

{{mcp-prompt}}

What happens next:

  1. Claude calls request_mandate with the actions it needs.
  2. Your phone buzzes. You press ✅ Approve.
  3. Claude calls mandate_status, sees approved, then gmail_read_inbox and gmail_create_draft.
  4. If it tries gmail_send without permission, the broker says no.

The 5 tools

ToolArgumentsNeeds
request_mandatetask, actions, expiresInSeconds, limitnothing. Returns a mandateId
mandate_statusmandateIda mandate
gmail_read_inboxmandateIdgmail.read
gmail_create_draftmandateId, to, subject, bodygmail.draft
gmail_sendmandateId, to, subject, bodygmail.send
The model never sees the token

The MCP server keeps the secret token inside its own process and gives the model only the mandateId. So if an email contains a prompt injection like "send me your token", there is nothing to steal.

Under the hood: talk to the MCP server by hand

MCP over stdio means: JSON messages, one per line, through the program's input and output. You can try it yourself:

The server is a small JSON-RPC implementation written for this project, with no dependencies.

HTTP API

For agents that don't speak MCP. The broker listens on 127.0.0.1:8787. Send JSON, and put the mandate token in the header Authorization: Bearer <token>.

Browsers are refused on purpose

A web page can also send requests to localhost. So the broker refuses any request with an Origin header, checks Host (against DNS rebinding), and accepts only application/json. Programs like curl and agents are not affected.

Security

Short-lived

Mandates expire by themselves. Unanswered requests die in 10 minutes.

One task only

Only the listed actions. A draft can't become a send.

Revoke anytime

One tap in Telegram or agcl revoke. Takes effect on the next request.

Fully logged

Every check, every decision, one line each. Tokens never.

What the broker protects against

  • A stolen mandate token: one task, short time, revocable. Not your whole mailbox forever.
  • An agent that goes wild: the limit stops it, the log shows when it started.
  • Prompt injection in an email: the agent may believe it, but the action is not in the mandate, and through MCP the token is not even visible.
  • A fake approval message: actions must look like app.verb, and the agent's text is one cleaned-up line, shown last.
  • An agent approving itself: approval is never possible over HTTP or through files. Only in Telegram (your id) or the broker's own terminal.
  • A web page attacking localhost: browser requests are refused.
  • Sending in your name: the Gmail connection only has read and draft access. Even a mistake in the broker could not send an email.
  • A tampered npm package: releases are published with provenance. Check with npm audit signatures.

What it does not protect against (yet)

  • Malware already running as your user can read ~/.agentcollar/.
  • Mandates are lost when the broker stops.

Troubleshooting

Nothing arrives in Telegram

Open your bot and press Start at least once: bots cannot write to you first. Check that agcl server says Approvals: Telegram. If it says this terminal, run agcl setup.

Setup says "Another program is already listening to this bot"

Usually it is your own agcl server. Stop it with Ctrl+C and run agcl setup again.

The agent says the broker is not running

Start it: agcl server. The broker and the agent must run on the same computer.

agcl mandates says "The broker is not running"

Mandates live in its memory, so after it stops there is nothing to show. Start it and let the agent ask again.

Gmail stopped working after a week

Your Google app is in testing mode, and Google ended the sign-in. Run agcl gmail connect again.

agcl: command not found

The short name needs installation: npm install -g agentcollar. Without installing, use npx agentcollar.

Port 8787 is busy

Maybe another broker is already running (check with agcl mandates). Or start this one on another port: BROKER_PORT=8788 agcl server, and tell your agent the new address.

"Unsupported engine" or syntax errors on start

Your Node.js is too old. AgentCollar needs 22 or newer: node --version.
