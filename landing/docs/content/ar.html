AgentCollar وسيط صغير يعمل على حاسوبك. يطلب منه وكيل الذكاء الاصطناعي تصريحًا قصيرًا لمهمة واحدة. وأنت توافق عليه في Telegram. ولا يرى الوكيل كلمة مرورك أبدًا.

AgentCollar ما زال جديدًا. لا تربط حسابات لا تحتمل خسارتها.

البداية

من لا شيء إلى وسيط يعمل في نحو ثلاث دقائق. تحتاج إلى Node.js 22 أو أحدث وحساب على Telegram. تحقّق من Node أولًا:

{{node-version}}

1. التثبيت

شغّله مرة واحدة دون تثبيت، أو ثبّته لتحصل على الأمر القصير agcl.

{{install}}

2. اربط بوت Telegram الخاص بك

أنشئ بوتًا عبر @BotFather (/newbot) وانسخ رمزه (token). ثم شغّل agcl. في المرة الأولى يبدأ معالج الإعداد من تلقاء نفسه.

3. أدخِل وكيلًا

اربط Claude Code عبر MCP، أو استدعِ واجهة HTTP من برنامجك الخاص. من الآن يمرّ كل طلب عبرك.

معالج الإعداد خطوة بخطوة

هذا ما ستراه. الأسطر التي تبدأ بـ $ هي ما تكتبه أنت.

{{setup}}

ما الذي حدث، سطرًا بسطر:

  1. الرمز مخفي أثناء الكتابة، ويُتحقَّق منه لدى Telegram. الرمز الخاطئ يعطي رسالة خطأ واضحة، لا انهيارًا.
  2. الرابط يحمل رمزًا يُستخدم مرة واحدة (K7P2M9QX). لا يُحتسب إلا أمر /start بهذا الرمز بالضبط، في محادثة خاصة. الغريب الذي يضغط Start في بوتك في اللحظة نفسها لا يستطيع أن يصبح الموافِق.
  3. "Is this you?" («هل هذا أنت؟») تتيح لك التحقق من الاسم بعينيك.
  4. تُحفظ إعداداتك في ~/.agentcollar/.env. لا يستطيع قراءته إلا مستخدم macOS الخاص بك. ويرسل لك البوت أيضًا: "AgentCollar is set up".
لا تملك Telegram؟ لا مشكلة.

أجب بـ n عن السؤال الأول. عندها يطلب الوسيط موافقتك مباشرة في الطرفية، بـ y أو N.

الموافقة في Telegram

عندما يطلب وكيل، تصل هذه الرسالة إلى بوتك:

{{telegram}}
  • الحقائق أولًا، وكلمات الوكيل في الأخير. «Actions» و«Lifetime» هما ما يفرضه الوسيط. أما المهمة فهي رواية الوكيل فقط، مضغوطة في سطر واحد، فلا يستطيع تزييف سطر «Actions:» إضافي.
  • إذا طلب الوكيل *.send، يظهر تحذير أولًا: "The agent asks for the right to SEND in your name" (الوكيل يطلب حق الإرسال باسمك).
  • بعد موافقتك تتحول الأزرار إلى 🛑 Revoke (إلغاء).
  • لا يستطيع الضغط إلا معرّف مستخدم Telegram الخاص بك. أما غيرك فيحصل على "No access".

كل فحص وكل قرار بشري يصبح سطرًا في ~/.agentcollar/audit.log. الأسطر تُضاف فقط ولا تُعدَّل أبدًا. هذا هو الملف الخام:

{{audit-raw}}

نصوص الوكلاء موضوعة بين علامتي تنصيص (JSON.stringify)، فلا يستطيع وكيل أن يضع فاصل أسطر في اسمه ليزيّف سطرًا. ولا يُكتب الرمز هنا أبدًا. يوضح العمود الأخير أي فحص حسم الأمر. يجعل agcl logs هذا مقروءًا (انظر أدناه).

ربط Gmail

افتراضيًا يستخدم الوسيط صندوق وارد وهميًا، لتجرّب كل شيء بأمان. حين تكون مستعدًا، اربط Gmail الحقيقي. يستطيع هذا الاتصال قراءة البريد وإنشاء المسودات. ولا يستطيع الإرسال أبدًا: الوسيط يمنعه، وGoogle تمنعه أيضًا، لأن الإرسال لم يُطلب قط.

  1. في Google Cloud، أنشئ عميل OAuth من نوع Desktop app ونزّل ملف JSON الخاص به.
  2. شغّل الأمر أدناه. سيُفتح متصفحك. اسمح بـ "read your email" و"create drafts".
  3. أعد تشغيل الوسيط.

الأمر agcl

agcl هو الاسم القصير لـ agentcollar. إنهما البرنامج نفسه: agcl watch = agentcollar watch. يعمل الاسم القصير بعد npm install -g agentcollar. ومع npx استخدم الاسم الطويل: npx agentcollar watch.

{{help}}

agcl

أمر «فقط اجعله يعمل». يعرض المقدمة، ويشغّل معالج الإعداد إن لم يكن Telegram معدًّا بعد، ثم يشغّل الوسيط. داخل برنامج نصي (لا أحد أمام الطرفية) يتخطى الأسئلة ويشغّل الوسيط.

agcl setup

يربط بوت Telegram الخاص بك. انظر الشرح الكامل. تشغيله مرة أخرى آمن: يسأل قبل استبدال .env موجود، ويُبقي الأسطر الأخرى (مثل BROKER_PORT).

agcl server

يشغّل الوسيط. يستمع على 127.0.0.1:8787 فقط: لا تستطيع برامج الحواسيب الأخرى الوصول إليه. أوقفه بـ Ctrl+C.

{{server}}
BROKER_PORT=9000
استخدم منفذًا آخر. ضعه في ~/.agentcollar/.env.

agcl watch

agcl revoke <id>

مفتاح الإيقاف الفوري. يتوقف التفويض عن العمل من الطلب التالي مباشرة. يعمل دون إنترنت. وتتحدّث رسالة Telegram أيضًا.

{{revoke}}

المعرّف موجود في رسالة Telegram وفي agcl mandates. الإلغاء لا يحتاج إلى رمز أبدًا: فهو لا يستطيع إلا سحب الوصول، ولا يمنحه أبدًا.

agcl mcp

يشغّل خادم MCP الذي يستخدمه Claude Code والوكلاء الآخرون. عادةً لا تشغّله بيدك: الوكيل يشغّله. انظر القسم التالي.

المقدمة

الميدالية الدوّارة هي الشعار مرسومًا بأحرف برايل (⣿⡇⠟). كل حرف يحمل 8 نقاط، فتصير الصورة أدق تفصيلًا من الأحرف العادية. تستمر نحو 1.7 ثانية، وأي مفتاح يتخطاها، ولا تظهر أبدًا في الأنابيب أو CI أو مع NO_COLOR أو --no-intro.

الاستخدام مع Claude Code

MCP (Model Context Protocol) لغة مشتركة بين وكيل الذكاء الاصطناعي وأدواته. AgentCollar يتحدث بها، لذا يستطيع Claude Code استخدام الوسيط بنفسه. أمر واحد يضيفه:

{{mcp-add}}

أبقِ agcl server يعمل في طرفية أخرى. ثم اطلب من Claude ببساطة:

{{mcp-prompt}}

ما الذي يحدث بعد ذلك:

  1. يستدعي Claude الأداة request_mandate مع الإجراءات التي يحتاجها.
  2. يهتز هاتفك. تضغط ✅ Approve.
  3. يستدعي Claude mandate_status، فيرى approved، ثم gmail_read_inbox وgmail_create_draft.
  4. إذا حاول gmail_send دون إذن، يقول الوسيط لا.

النموذج لا يرى الرمز أبدًا

يحتفظ خادم MCP بالرمز السري داخل عمليته الخاصة، ولا يعطي النموذج إلا mandateId. فإذا احتوت رسالة بريد على حقن أوامر (prompt injection) مثل «أرسل لي رمزك»، فلا يوجد ما يُسرق.

من الداخل: تحدّث مع خادم MCP يدويًا

MCP عبر stdio يعني: رسائل JSON، واحدة في كل سطر، عبر مدخلات البرنامج ومخرجاته. يمكنك أن تجرّب بنفسك:

{{mcp-raw}}

الخادم تنفيذ صغير لـ JSON-RPC كُتب لهذا المشروع، بلا أي اعتماديات.

المتصفحات تُرفض عن قصد

يمكن لصفحة ويب أيضًا أن ترسل طلبات إلى localhost. لذلك يرفض الوسيط أي طلب يحمل ترويسة Origin، ويتحقق من Host (ضد DNS rebinding)، ولا يقبل إلا application/json. البرامج مثل curl والوكلاء لا تتأثر.

الأمان

قصير العمر

التفويضات تنتهي من تلقاء نفسها. والطلبات التي لا يُجاب عنها تموت بعد 10 دقائق.

مهمة واحدة فقط

الإجراءات المدرجة فقط. المسودة لا يمكن أن تتحول إلى إرسال.

ألغِ في أي وقت

نقرة واحدة في Telegram أو agcl revoke. يسري من الطلب التالي.

كل شيء مسجَّل

كل فحص وكل قرار، سطر لكل منهما. والرموز أبدًا.

ما يحميك منه الوسيط

  • رمز تفويض مسروق: مهمة واحدة، وقت قصير، قابل للإلغاء. لا صندوق بريدك كله إلى الأبد.
  • وكيل يخرج عن السيطرة: الحد يوقفه، والسجل يبيّن متى بدأ.
  • حقن أوامر في رسالة بريد: قد يصدّقه الوكيل، لكن الإجراء ليس ضمن التفويض، وعبر MCP لا يكون الرمز مرئيًا أصلًا.
  • رسالة موافقة مزيّفة: يجب أن تكون الإجراءات بصيغة app.verb، ونص الوكيل سطر واحد منظَّف يُعرض في الأخير.
  • وكيل يوافق على نفسه: الموافقة غير ممكنة أبدًا عبر HTTP أو عبر الملفات. فقط في Telegram (معرّفك) أو في طرفية الوسيط نفسه.
  • صفحة ويب تهاجم localhost: طلبات المتصفحات تُرفض.
  • الإرسال باسمك: لاتصال Gmail صلاحية القراءة والمسودات فقط. حتى خطأ في الوسيط لا يستطيع إرسال رسالة.
  • حزمة npm معدّلة: تُنشر الإصدارات مع provenance (مصدر يمكن التحقق منه). تحقّق بـ npm audit signatures.

ما لا يحميك منه (بعد)

  • البرمجيات الخبيثة التي تعمل أصلًا باسم مستخدمك تستطيع قراءة ~/.agentcollar/.
  • تضيع التفويضات حين يتوقف الوسيط.

حل المشكلات

لا يصل شيء إلى Telegram

افتح بوتك واضغط Start مرة واحدة على الأقل: البوتات لا تستطيع أن تبدأ مراسلتك. تحقّق من أن agcl server يعرض Approvals: Telegram. إن عرض this terminal، فشغّل agcl setup.

يقول الإعداد "Another program is already listening to this bot"

(برنامج آخر يستمع بالفعل إلى هذا البوت.) غالبًا هو agcl server الخاص بك. أوقفه بـ Ctrl+C وشغّل agcl setup مرة أخرى.

يقول الوكيل إن الوسيط لا يعمل

شغّله: agcl server. يجب أن يعمل الوسيط والوكيل على الحاسوب نفسه.

يقول agcl mandates "The broker is not running"

التفويضات تعيش في ذاكرته، فبعد توقفه لا يوجد ما يُعرض. شغّله ودع الوكيل يطلب من جديد.

توقف Gmail عن العمل بعد أسبوع

تطبيقك في Google في وضع الاختبار، وقد أنهت Google تسجيل الدخول. شغّل agcl gmail connect مرة أخرى.

agcl: command not found

الاسم القصير يحتاج إلى تثبيت: npm install -g agentcollar. ودون تثبيت، استخدم npx agentcollar.

المنفذ 8787 مشغول

ربما يعمل وسيط آخر بالفعل (تحقّق بـ agcl mandates). أو شغّل هذا على منفذ آخر: BROKER_PORT=8788 agcl server، وأخبر وكيلك بالعنوان الجديد.

"Unsupported engine" أو أخطاء صياغة عند التشغيل

إصدار Node.js لديك قديم جدًا. يحتاج AgentCollar إلى الإصدار 22 أو أحدث: node --version.
