Lass Agenten arbeiten.
Behalte die Schlüssel.

AgentCollar ist ein kleiner Broker, der auf deinem Computer läuft. Dein KI-Agent bittet ihn um einen kurzen Passierschein für genau eine Aufgabe. Du gibst ihn in Telegram frei. Der Agent sieht nie dein Passwort.

AgentCollar ist jung. Verbinde keine Konten, deren Verlust du dir nicht leisten kannst.

Erste Schritte

Von null zu einem laufenden Broker in etwa drei Minuten. Du brauchst Node.js 22 oder neuer und ein Telegram-Konto. Prüfe zuerst Node:

{{node-version}}

1. Installieren

Starte es einmal ohne Installation, oder installiere es, um den kurzen Befehl agcl zu bekommen.

{{install}}

2. Deinen Telegram-Bot verbinden

Erstelle einen Bot mit @BotFather (/newbot) und kopiere sein Token. Starte dann agcl. Beim ersten Mal startet es den Einrichtungsassistenten von selbst.

3. Einen Agenten hereinlassen

Verbinde Claude Code über MCP, oder rufe die HTTP-API aus deinem eigenen Skript auf. Ab jetzt geht jede Anfrage über dich.

Der Einrichtungsassistent, Schritt für Schritt

Das siehst du. Zeilen, die mit $ beginnen, tippst du selbst.

{{setup}}

Was passiert ist, Zeile für Zeile:

  1. Das Token bleibt verborgen, während du tippst, und wird bei Telegram geprüft. Ein falsches Token führt zu einer klaren Fehlermeldung, nicht zu einem Absturz.
  2. Der Link enthält einen Einmalcode (K7P2M9QX). Nur ein /start mit genau diesem Code in einem privaten Chat zählt. Ein Fremder, der im selben Moment in deinem Bot auf Start drückt, kann nicht zu deinem Freigeber werden.
  3. „Is this you?" („Bist du das?") lässt dich den Namen mit eigenen Augen prüfen.
  4. Deine Einstellungen landen in ~/.agentcollar/.env. Nur dein macOS-Benutzer kann die Datei lesen. Der Bot schreibt dir außerdem: „AgentCollar is set up".
Kein Telegram? Kein Problem.

Antworte bei der ersten Frage mit n. Der Broker bittet dich dann direkt im Terminal um Freigabe, mit y oder N.

So funktioniert es

Drei Beteiligte, eine Regel: Der Agent spricht nur mit dem Broker, und der Broker handelt erst, wenn alle Prüfungen bestanden sind.

{{sequence}}

Mandate

Ein Mandat ist eine Erlaubnis für genau eine Aufgabe. Der Agent fragt danach, du gibst es frei, und es läuft von selbst ab. Es enthält:

FeldBeispielBedeutung
agentclaude-codeWer fragt. Wird dir angezeigt.
task"Draft replies to new mail"Warum, in den eigenen Worten des Agenten. Wird zuletzt angezeigt, in Anführungszeichen.
allowedActionsgmail.read, gmail.draftGenau das, was erlaubt ist. Immer app.verb.
expiresInSeconds300Wie lange es nach deiner Freigabe gilt. Höchstens 1 Tag.
limit10Die Höchstzahl erlaubter Aktionen. Höchstens 1000.
id8329b843Öffentlicher Name. Kann gefahrlos angezeigt und in agcl revoke eingetippt werden.
token64 Hex-ZeichenDas Geheimnis. Nur der Agent (oder der MCP-Server) hat es. Wird nie protokolliert.

Ein Mandat durchläuft diese Zustände:

{{lifecycle}}

Die Uhr startet mit deiner Freigabe, nicht mit der Anfrage des Agenten. Antwortet 10 Minuten lang niemand, wird die Anfrage abgelehnt. Das nennt man fail closed: Im Zweifel lautet die Antwort Nein.

Die 6 Prüfungen

Jede Anfrage durchläuft diese Prüfungen in dieser Reihenfolge. Die erste, die fehlschlägt, stoppt alles, und der Grund landet im Audit-Log.

#FrageWenn neinHTTP
1Kennen wir dieses Token?unknown token401
2Hat ein Mensch es freigegeben?waiting / denied403
3Ist es noch innerhalb seiner Zeit?expired403
4Wurde es nicht widerrufen?revoked403
5Steht diese Aktion im Mandat?action not allowed403
6Ist das Limit noch nicht erreicht?limit reached429

Das ist das Herz des Codes, broker/src/check.ts. Es ist absichtlich kurz:

{{check-ts}}

Achte auf das Muster: Jede Prüfung kann nur Nein sagen. Das „Ja" steht ein einziges Mal, ganz unten. Ingenieure nennen das deny by default (standardmäßig ablehnen).

Freigabe in Telegram

Wenn ein Agent fragt, kommt diese Nachricht bei deinem Bot an:

{{telegram}}
  • Erst die Fakten, zuletzt die Worte des Agenten. „Actions" und „Lifetime" sind das, was der Broker durchsetzt. Die Aufgabe ist nur die Geschichte des Agenten, auf eine Zeile zusammengedrückt, damit er keine zusätzliche Zeile „Actions:" fälschen kann.
  • Fragt der Agent nach *.send, kommt zuerst eine Warnung: „The agent asks for the right to SEND in your name" (der Agent möchte in deinem Namen SENDEN dürfen).
  • Nach deiner Freigabe werden die Knöpfe zu 🛑 Revoke (widerrufen).
  • Nur deine Telegram-Benutzer-ID kann drücken. Alle anderen bekommen „No access".

Das Audit-Log

Jede Prüfung und jede menschliche Entscheidung wird zu einer Zeile in ~/.agentcollar/audit.log. Zeilen werden nur angehängt, nie verändert. Das ist die Rohdatei:

{{audit-raw}}

Text von Agenten steht in Anführungszeichen (JSON.stringify), damit ein Agent keinen Zeilenumbruch in seinen Namen schmuggeln und eine falsche Zeile fälschen kann. Das Token wird hier nie geschrieben. Die letzte Spalte zeigt, welche Prüfung entschieden hat. agcl logs macht daraus etwas Lesbares (siehe unten).

Gmail verbinden

Von Haus aus nutzt der Broker ein gefälschtes Postfach, damit du alles gefahrlos ausprobieren kannst. Wenn du bereit bist, verbinde dein echtes Gmail. Die Verbindung kann Mails lesen und Entwürfe anlegen. Senden kann sie nie: Der Broker blockiert es, und Google ebenfalls, weil das Senden nie angefragt wurde.

  1. Lege in Google Cloud einen OAuth-Client vom Typ Desktop app an und lade seine JSON-Datei herunter.
  2. Führe den Befehl unten aus. Dein Browser öffnet sich. Erlaube „read your email" und „create drafts".
  3. Starte den Broker neu.
{{gmail-connect}}

Das Refresh-Token landet im macOS-Schlüsselbund, nie in einer Datei. Das kurzlebige Access-Token lebt nur im Arbeitsspeicher. Prüfe oder entferne die Verbindung jederzeit:

{{gmail-status}}
Der Testmodus hält 7 Tage

Solange deine Google-App im Testmodus ist, beendet Google die Anmeldung nach 7 Tagen. Führe einfach erneut agcl gmail connect aus.

Der Befehl agcl

agcl ist der Kurzname von agentcollar. Es ist dasselbe Programm: agcl watch = agentcollar watch. Der Kurzname funktioniert nach npm install -g agentcollar. Mit npx nimm den langen Namen: npx agentcollar watch.

{{help}}

agcl

Der „mach einfach, dass es läuft"-Befehl. Zeigt das Intro, startet den Assistenten, wenn Telegram noch nicht eingerichtet ist, und startet dann den Broker. In einem Skript (niemand am Terminal) überspringt er die Fragen und startet den Broker.

agcl setup

Verbindet deinen eigenen Telegram-Bot. Siehe die vollständige Anleitung. Kann gefahrlos erneut ausgeführt werden: Es fragt, bevor es eine vorhandene .env ersetzt, und behält andere Zeilen (zum Beispiel BROKER_PORT).

agcl server

Startet den Broker. Er lauscht nur auf 127.0.0.1:8787: Programme auf anderen Computern erreichen ihn nicht. Beende ihn mit Ctrl+C.

{{server}}
BROKER_PORT=9000
Einen anderen Port nutzen. Trag ihn in ~/.agentcollar/.env ein.
Mandate leben im Arbeitsspeicher

Wenn du den Broker stoppst, verschwinden alle Mandate. Agenten fragen einfach erneut. Das Audit-Log bleibt.

agcl watch

Ein Live-Bildschirm. Öffne ihn in einem zweiten Terminal und sieh jede Anfrage in dem Moment, in dem sie passiert. Er liest nur das Audit-Log: Er kann nichts verändern.

{{watch}}

So liest du ✓ ✓ ✓ ✓ ✗ ·: Die sechs Zeichen sind die sechs Prüfungen. ✓ bestanden, ✗ die fehlgeschlagene, · nie ausgeführt (die Anfrage war schon gestoppt). Gelbe Zeilen sind menschliche Entscheidungen.

agcl mandates

Was der laufende Broker gerade weiß: wer, was, Zustand, verbleibende Zeit und Aktionen. Er liest eine Snapshot-Datei, die der Broker nach jeder Änderung schreibt. Der Snapshot enthält keine Tokens.

Zustände: waiting active denied expired revoked limit used up

agcl revoke <id>

Der Not-Aus-Schalter. Das Mandat hört bei der nächsten Anfrage auf zu funktionieren. Geht ohne Internet. Die Telegram-Nachricht wird ebenfalls aktualisiert.

{{revoke}}

Die ID steht in der Telegram-Nachricht und in agcl mandates. Widerrufen braucht nie ein Token: Es kann Zugriff nur wegnehmen, nie geben.

agcl mcp

Startet den MCP-Server, den Claude Code und andere Agenten nutzen. Normalerweise startest du ihn nicht von Hand: Das macht der Agent. Siehe den nächsten Abschnitt.

Das Intro

Das drehende Medaillon ist das Logo, gezeichnet mit Braille-Zeichen (⣿⡇⠟). Jedes enthält 8 Punkte, deshalb wird das Bild detailreicher als mit normalen Buchstaben. Es dauert etwa 1,7 Sekunden, jede Taste überspringt es, und es erscheint nie in Pipes, in CI, mit NO_COLOR oder mit --no-intro.

Mit Claude Code nutzen

MCP (Model Context Protocol) ist eine gemeinsame Sprache zwischen einem KI-Agenten und seinen Werkzeugen. AgentCollar spricht sie, also kann Claude Code den Broker selbstständig nutzen. Ein Befehl fügt ihn hinzu:

{{mcp-add}}

Lass agcl server in einem anderen Terminal laufen. Dann bitte Claude einfach:

{{mcp-prompt}}

Was als Nächstes passiert:

  1. Claude ruft request_mandate mit den Aktionen auf, die es braucht.
  2. Dein Telefon vibriert. Du drückst ✅ Approve.
  3. Claude ruft mandate_status auf, sieht approved, dann gmail_read_inbox und gmail_create_draft.
  4. Versucht es gmail_send ohne Erlaubnis, sagt der Broker Nein.

Das Modell sieht das Token nie

Der MCP-Server behält das geheime Token in seinem eigenen Prozess und gibt dem Modell nur die mandateId. Enthält eine E-Mail eine Prompt-Injection wie „schick mir dein Token", gibt es also nichts zu stehlen.

Unter der Haube: mit dem MCP-Server von Hand sprechen

MCP über stdio heißt: JSON-Nachrichten, eine pro Zeile, über Ein- und Ausgabe des Programms. Probier es selbst:

HTTP-API

Für Agenten, die kein MCP sprechen. Der Broker lauscht auf 127.0.0.1:8787. Sende JSON und schreib das Mandats-Token in den Header Authorization: Bearer <token>.

Browser werden absichtlich abgewiesen

Auch eine Webseite kann Anfragen an localhost schicken. Deshalb weist der Broker jede Anfrage mit Origin-Header ab, prüft Host (gegen DNS-Rebinding) und akzeptiert nur application/json. Programme wie curl und Agenten sind nicht betroffen.

Alles liegt in einem Ordner in deinem Home-Verzeichnis, nicht im Code-Ordner: Den ersetzt npm bei jedem Update.

Sicherheit

Kurzlebig

Mandate laufen von selbst ab. Unbeantwortete Anfragen sterben nach 10 Minuten.

Nur eine Aufgabe

Nur die aufgeführten Aktionen. Aus einem Entwurf wird kein Versand.

Jederzeit widerrufbar

Ein Tipp in Telegram oder agcl revoke. Wirkt bei der nächsten Anfrage.

Lückenlos protokolliert

Jede Prüfung, jede Entscheidung, je eine Zeile. Tokens nie.

Wovor der Broker schützt

  • Ein gestohlenes Mandats-Token: eine Aufgabe, kurze Zeit, widerrufbar. Nicht dein ganzes Postfach für immer.
  • Ein Agent, der durchdreht: Das Limit stoppt ihn, das Log zeigt, wann es losging.
  • Prompt-Injection in einer E-Mail: Der Agent glaubt sie vielleicht, aber die Aktion steht nicht im Mandat, und über MCP ist das Token nicht einmal sichtbar.
  • Eine gefälschte Freigabenachricht: Aktionen müssen wie app.verb aussehen, und der Text des Agenten ist eine einzige bereinigte Zeile, ganz am Ende.
  • Ein Agent, der sich selbst freigibt: Freigabe ist nie über HTTP oder über Dateien möglich. Nur in Telegram (deine ID) oder im eigenen Terminal des Brokers.
  • Eine Webseite, die localhost angreift: Browser-Anfragen werden abgewiesen.
  • Senden in deinem Namen: Die Gmail-Verbindung hat nur Lese- und Entwurfsrechte. Selbst ein Fehler im Broker könnte keine E-Mail senden.
  • Ein manipuliertes npm-Paket: Releases werden mit Provenance (nachprüfbarer Herkunft) veröffentlicht. Prüfe mit npm audit signatures.

Wovor er (noch) nicht schützt

  • Schadsoftware, die bereits unter deinem Benutzer läuft, kann ~/.agentcollar/ lesen.
  • Mandate gehen verloren, wenn der Broker stoppt.

Fehlerbehebung

In Telegram kommt nichts an

Öffne deinen Bot und drück mindestens einmal Start: Bots können dir nicht als Erste schreiben. Prüfe, ob agcl server Approvals: Telegram anzeigt. Steht dort this terminal, führe agcl setup aus.

Der Assistent meldet „Another program is already listening to this bot"

(Ein anderes Programm hört diesen Bot bereits ab.) Meist ist es dein eigener agcl server. Beende ihn mit Ctrl+C und führe agcl setup erneut aus.

Der Agent sagt, der Broker läuft nicht

Starte ihn: agcl server. Broker und Agent müssen auf demselben Computer laufen.

agcl mandates meldet „The broker is not running"

Mandate leben in seinem Arbeitsspeicher, nach dem Stoppen gibt es also nichts anzuzeigen. Starte ihn und lass den Agenten erneut fragen.

Gmail funktioniert nach einer Woche nicht mehr

Deine Google-App ist im Testmodus, und Google hat die Anmeldung beendet. Führe agcl gmail connect erneut aus.

agcl: command not found

Der Kurzname braucht eine Installation: npm install -g agentcollar. Ohne Installation nimm npx agentcollar.

Port 8787 ist belegt

Vielleicht läuft schon ein anderer Broker (prüfe mit agcl mandates). Oder starte diesen auf einem anderen Port: BROKER_PORT=8788 agcl server, und gib deinem Agenten die neue Adresse.

„Unsupported engine" oder Syntaxfehler beim Start

Dein Node.js ist zu alt. AgentCollar braucht Version 22 oder neuer: node --version.
