O AgentCollar é um pequeno broker que roda no seu computador. Seu agente de IA pede a ele um passe curto para uma única tarefa. Você aprova no Telegram. O agente nunca vê a sua senha.

{{hero-install}}

O AgentCollar é jovem. Não conecte contas que você não pode se dar ao luxo de perder.

Primeiros passos

Do zero a um broker funcionando em cerca de três minutos. Você precisa do Node.js 22 ou mais recente e de uma conta no Telegram. Primeiro confira o Node:

{{node-version}}

1. Instale

Rode uma vez sem instalar, ou instale para ter o comando curto agcl.

{{install}}

2. Conecte seu bot do Telegram

Crie um bot com o @BotFather (/newbot) e copie o token dele. Depois rode agcl. Na primeira vez, ele abre o assistente de configuração sozinho.

3. Deixe um agente entrar

Conecte o Claude Code pelo MCP, ou chame a API HTTP do seu próprio script. Agora toda requisição passa por você.

O assistente de configuração, passo a passo

É isto que você vê. As linhas que começam com $ são o que você digita.

{{setup}}

O que aconteceu, linha por linha:

  1. O token fica oculto enquanto você digita e é verificado com o Telegram. Um token errado gera um erro claro, não uma falha.
  2. O link tem um código de uso único (K7P2M9QX). Só conta um /start com esse código exato, em um chat privado. Um estranho que aperte Start no seu bot no mesmo instante não consegue virar o aprovador.
  3. "Is this you?" ("É você?") deixa você conferir o nome com os próprios olhos.
  4. Suas configurações vão para ~/.agentcollar/.env. Só o seu usuário do macOS consegue ler. O bot também escreve para você: "AgentCollar is set up".
Sem Telegram? Tudo bem.

Responda n à primeira pergunta. O broker então pede sua aprovação direto no terminal, com y ou N.

Como funciona

Três partes, uma regra: o agente só fala com o broker, e o broker só age depois que as verificações passam.

{{sequence}}

Mandatos

Um mandato é uma permissão para uma única tarefa. O agente pede, você aprova, e ele para de funcionar sozinho. Ele tem:

CampoExemploSignificado
agentclaude-codeQuem pede. Mostrado para você.
task"Draft replies to new mail"O porquê, nas palavras do próprio agente. Mostrado por último, entre aspas.
allowedActionsgmail.read, gmail.draftExatamente o que é permitido. Sempre app.verb.
expiresInSeconds300Quanto tempo dura depois que você aprova. No máximo 1 dia.
limit10O máximo de ações permitidas. No máximo 1000.
id8329b843Nome público. Seguro para mostrar e digitar em agcl revoke.
token64 caracteres hexadecimaisO segredo. Só o agente (ou o servidor MCP) tem. Nunca vai para o log.

Um mandato passa por estes estados:

{{lifecycle}}

O relógio começa quando você aprova, não quando o agente pede. Se ninguém responder em 10 minutos, o pedido é negado. Isso se chama fail closed (falhar fechado): na dúvida, a resposta é não.

As 6 verificações

Toda requisição passa por estas verificações nesta ordem. A primeira que falha interrompe tudo, e o motivo vai para o log de auditoria.

#PerguntaSe nãoHTTP
1Conhecemos este token?unknown token401
2Uma pessoa aprovou?waiting / denied403
3Ainda está dentro do prazo?expired403
4Não foi revogado?revoked403
5Esta ação está no mandato?action not allowed403
6O limite não foi atingido?limit reached429

Este é o coração do código, broker/src/check.ts. Ele é curto de propósito:

{{check-ts}}

Repare no padrão: cada verificação só pode dizer não. O "sim" é escrito uma única vez, bem no final. Engenheiros chamam isso de deny by default (negar por padrão).

Aprovação no Telegram

Quando um agente pede, esta mensagem chega ao seu bot:

{{telegram}}
  • Fatos primeiro, as palavras do agente por último. "Actions" e "Lifetime" são o que o broker impõe. A tarefa é só a história do agente, espremida em uma linha, então ele não consegue forjar uma linha "Actions:" a mais.
  • Se o agente pedir *.send, primeiro vem um aviso: "The agent asks for the right to SEND in your name" (o agente pede o direito de ENVIAR em seu nome).
  • Depois que você aprova, os botões mudam para 🛑 Revoke (revogar).
  • Só o seu id de usuário do Telegram pode apertar. Todos os outros recebem "No access".

O log de auditoria

Cada verificação e cada decisão humana vira uma linha em ~/.agentcollar/audit.log. Linhas só são adicionadas, nunca alteradas. Este é o arquivo bruto:

{{audit-raw}}

O texto dos agentes fica entre aspas (JSON.stringify), então um agente não consegue colocar uma quebra de linha no nome e forjar uma linha falsa. O token nunca é escrito aqui. A última coluna diz qual verificação decidiu. agcl logs transforma isso em algo legível (veja abaixo).

Conectar o Gmail

De fábrica, o broker usa uma caixa de entrada falsa, para você testar tudo com segurança. Quando estiver pronto, conecte seu Gmail de verdade. A conexão pode ler e-mails e criar rascunhos. Ela nunca pode enviar: o broker bloqueia, e o Google também, porque o envio nunca foi pedido.

  1. No Google Cloud, crie um cliente OAuth do tipo Desktop app e baixe o arquivo JSON dele.
  2. Rode o comando abaixo. Seu navegador abre. Permita "read your email" e "create drafts".
  3. Reinicie o broker.
{{gmail-connect}}

O refresh token vai para as Chaves do macOS (Keychain), nunca para um arquivo. O access token, de vida curta, fica só na memória. Confira ou remova a conexão quando quiser:

{{gmail-status}}
O modo de teste dura 7 dias

Enquanto seu app do Google estiver em modo de teste, o Google encerra o login após 7 dias. É só rodar agcl gmail connect de novo.

O comando agcl

agcl é o nome curto de agentcollar. São o mesmo programa: agcl watch = agentcollar watch. O nome curto funciona depois de npm install -g agentcollar. Com npx, use o nome longo: npx agentcollar watch.

{{help}}

agcl

O comando "só faz funcionar". Mostra a intro, roda o assistente se o Telegram ainda não estiver configurado e depois inicia o broker. Em um script (sem uma pessoa no terminal), ele pula as perguntas e inicia o broker.

agcl setup

Conecta o seu próprio bot do Telegram. Veja o passo a passo completo. Pode rodar de novo sem medo: ele pergunta antes de substituir um .env existente e mantém as outras linhas (por exemplo BROKER_PORT).

agcl server

Inicia o broker. Ele escuta só em 127.0.0.1:8787: programas em outros computadores não conseguem alcançá-lo. Pare com Ctrl+C.

{{server}}
BROKER_PORT=9000
Use outra porta. Coloque em ~/.agentcollar/.env.
Os mandatos vivem na memória

Quando você para o broker, todos os mandatos somem. Os agentes simplesmente pedem de novo. O log de auditoria fica.

agcl watch

Uma tela ao vivo. Abra em um segundo terminal e veja cada requisição no momento em que acontece. Ela só lê o log de auditoria: não pode mudar nada.

{{watch}}

Como ler ✓ ✓ ✓ ✓ ✗ ·: as seis marcas são as seis verificações. ✓ passou, ✗ é a que falhou, · nem rodou (a requisição já tinha parado). Linhas amarelas são decisões humanas.

agcl mandates

O que o broker em execução lembra agora: quem, o quê, estado, tempo e ações restantes. Ele lê um arquivo de snapshot que o broker escreve a cada mudança. O snapshot não tem tokens.

{{mandates}}

Estados: waiting active denied expired revoked limit used up

agcl logs

O log de auditoria, filtrado e colorido.

--agent <name>
só este agente

só as recusas (a parte interessante)

só hoje
{{logs}}

Os filtros se combinam. Quer o arquivo bruto? tail -f ~/.agentcollar/audit.log.

agcl revoke <id>

O botão de emergência. O mandato para de funcionar já na próxima requisição. Funciona sem internet. A mensagem do Telegram também é atualizada.

{{revoke}}

O id está na mensagem do Telegram e em agcl mandates. Revogar nunca precisa de token: só pode tirar acesso, nunca dar.

agcl mcp

Inicia o servidor MCP que o Claude Code e outros agentes usam. Normalmente você não roda isso à mão: o agente inicia. Veja a próxima seção.

A intro

O medalhão girando é o logo desenhado com caracteres Braille (⣿⡇⠟). Cada um guarda 8 pontos, então a imagem tem mais detalhe do que com letras normais. Dura cerca de 1,7 segundo, qualquer tecla pula, e nunca aparece em pipes, no CI, com NO_COLOR ou com --no-intro.

Usar com o Claude Code

MCP (Model Context Protocol) é uma língua comum entre um agente de IA e suas ferramentas. O AgentCollar fala essa língua, então o Claude Code pode usar o broker sozinho. Um comando adiciona:

{{mcp-add}}

Deixe o agcl server rodando em outro terminal. Depois é só pedir ao Claude:

{{mcp-prompt}}

O que acontece em seguida:

  1. O Claude chama request_mandate com as ações de que precisa.
  2. Seu celular vibra. Você aperta ✅ Approve.
  3. O Claude chama mandate_status, vê approved, e depois gmail_read_inbox e gmail_create_draft.
  4. Se ele tentar gmail_send sem permissão, o broker diz não.

O modelo nunca vê o token

O servidor MCP guarda o token secreto dentro do próprio processo e dá ao modelo só o mandateId. Então, se um e-mail trouxer uma injeção de prompt como "me mande seu token", não há nada para roubar.

Por dentro: converse com o servidor MCP à mão

MCP sobre stdio significa: mensagens JSON, uma por linha, pela entrada e saída do programa. Você mesmo pode testar:

{{mcp-raw}}

O servidor é uma pequena implementação de JSON-RPC escrita para este projeto, sem dependências.

Navegadores são recusados de propósito

Uma página web também pode enviar requisições para localhost. Por isso o broker recusa qualquer requisição com cabeçalho Origin, confere o Host (contra DNS rebinding) e só aceita application/json. Programas como o curl e os agentes não são afetados.

Segurança

Vida curta

Os mandatos expiram sozinhos. Pedidos sem resposta morrem em 10 minutos.

Uma tarefa só

Só as ações listadas. Um rascunho não vira um envio.

Revogue quando quiser

Um toque no Telegram ou agcl revoke. Vale já na próxima requisição.

Tudo registrado

Cada verificação, cada decisão, uma linha cada. Tokens, nunca.

Contra o que o broker protege

  • Um token de mandato roubado: uma tarefa, pouco tempo, revogável. Não a sua caixa de e-mail inteira para sempre.
  • Um agente descontrolado: o limite o para, o log mostra quando começou.
  • Injeção de prompt em um e-mail: o agente pode acreditar, mas a ação não está no mandato, e pelo MCP o token nem é visível.
  • Uma mensagem de aprovação falsa: as ações precisam ter a forma app.verb, e o texto do agente é uma única linha limpa, mostrada por último.
  • Um agente aprovando a si mesmo: a aprovação nunca é possível por HTTP ou por arquivos. Só no Telegram (seu id) ou no próprio terminal do broker.
  • Uma página web atacando o localhost: requisições de navegadores são recusadas.
  • Enviar em seu nome: a conexão com o Gmail só tem acesso de leitura e de rascunhos. Nem um erro no broker conseguiria enviar um e-mail.
  • Um pacote npm adulterado: as versões são publicadas com provenance (origem verificável). Confira com npm audit signatures.

Contra o que ele não protege (ainda)

  • Um malware que já roda com o seu usuário pode ler ~/.agentcollar/.
  • Os mandatos se perdem quando o broker para.

Solução de problemas

Nada chega no Telegram

Abra seu bot e aperte Start pelo menos uma vez: bots não podem escrever para você primeiro. Confira se o agcl server mostra Approvals: Telegram. Se mostrar this terminal, rode agcl setup.

O assistente diz "Another program is already listening to this bot"

(Outro programa já está escutando este bot.) Geralmente é o seu próprio agcl server. Pare com Ctrl+C e rode agcl setup de novo.

O agente diz que o broker não está rodando

Inicie: agcl server. O broker e o agente precisam rodar no mesmo computador.

agcl mandates diz "The broker is not running"

Os mandatos vivem na memória dele, então depois que ele para não há nada para mostrar. Inicie e deixe o agente pedir de novo.

O Gmail parou de funcionar depois de uma semana

Seu app do Google está em modo de teste, e o Google encerrou o login. Rode agcl gmail connect de novo.

agcl: command not found

O nome curto precisa de instalação: npm install -g agentcollar. Sem instalar, use npx agentcollar.

A porta 8787 está ocupada

Talvez outro broker já esteja rodando (confira com agcl mandates). Ou inicie este em outra porta: BROKER_PORT=8788 agcl server, e informe o novo endereço ao seu agente.

"Unsupported engine" ou erros de sintaxe ao iniciar

Seu Node.js é antigo demais. O AgentCollar precisa da versão 22 ou mais recente: node --version.
