AgentCollar es un pequeño broker que se ejecuta en tu ordenador. Tu agente de IA le pide un pase corto para una sola tarea. Tú lo apruebas en Telegram. El agente nunca ve tu contraseña.

Primeros pasos

De cero a un broker funcionando en unos tres minutos. Necesitas Node.js 22 o posterior y una cuenta de Telegram. Primero comprueba Node:

1. Instalar

Ejecútalo una vez sin instalar, o instálalo para tener el comando corto agcl.

2. Conecta tu bot de Telegram

Crea un bot con @BotFather (/newbot) y copia su token. Después ejecuta agcl. La primera vez, inicia el asistente de configuración por sí solo.

3. Deja entrar a un agente

El asistente de configuración, paso a paso

Esto es lo que verás. Las líneas que empiezan con $ son lo que escribes tú.

{{setup}}

Qué pasó, línea por línea:

  1. El token queda oculto mientras escribes y se verifica con Telegram. Un token incorrecto produce un error claro, no un fallo.
  2. El enlace lleva un código de un solo uso (K7P2M9QX). Solo cuenta un /start con ese código exacto, en un chat privado. Un desconocido que pulse Start en tu bot en ese mismo momento no puede convertirse en quien aprueba.
  3. "Is this you?" («¿Eres tú?») te permite comprobar el nombre con tus propios ojos.
  4. Tu configuración se guarda en ~/.agentcollar/.env. Solo tu usuario de macOS puede leerla. El bot también te escribe: "AgentCollar is set up".
¿Sin Telegram? No pasa nada.

Responde n a la primera pregunta. Entonces el broker te pide aprobar directamente en la terminal, con y o N.

Cómo funciona

Tres partes, una regla: el agente solo habla con el broker, y el broker solo actúa cuando pasan las comprobaciones.

{{sequence}}

Mandatos

Un mandato es un permiso para una sola tarea. El agente lo pide, tú lo apruebas, y deja de funcionar por sí solo. Contiene:

CampoEjemploSignificado
agentclaude-codeQuién lo pide. Se te muestra.
task"Draft replies to new mail"Por qué, con las palabras del propio agente. Se muestra al final, entre comillas.
allowedActionsgmail.read, gmail.draftExactamente lo que está permitido. Siempre app.verb.
expiresInSeconds300Cuánto dura después de que lo apruebes. Como máximo 1 día.
limit10El número máximo de acciones permitidas. Como máximo 1000.
id8329b843Nombre público. Se puede mostrar y escribir en agcl revoke sin riesgo.
token64 caracteres hexadecimalesEl secreto. Solo lo tiene el agente (o el servidor MCP). Nunca se registra.

Un mandato pasa por estos estados:

{{lifecycle}}

El reloj empieza cuando apruebas, no cuando el agente pide. Si nadie responde en 10 minutos, la petición se deniega. Esto se llama fail closed (fallar cerrado): ante la duda, la respuesta es no.

Las 6 comprobaciones

Cada petición pasa por estas comprobaciones en este orden. La primera que falla lo detiene todo, y el motivo va al registro de auditoría.

#PreguntaSi noHTTP
1¿Conocemos este token?unknown token401
2¿Lo aprobó una persona?waiting / denied403
3¿Sigue dentro de su tiempo?expired403
4¿No fue revocado?revoked403
5¿Esta acción está en el mandato?action not allowed403
6¿No se alcanzó el límite?limit reached429

Este es el corazón del código, broker/src/check.ts. Es corto a propósito:

{{check-ts}}

Fíjate en el patrón: cada comprobación solo puede decir no. El "sí" se escribe una sola vez, abajo del todo. Los ingenieros lo llaman deny by default (denegar por defecto).

Aprobación en Telegram

Cuando un agente pide algo, este mensaje llega a tu bot:

{{telegram}}
  • Primero los hechos, al final las palabras del agente. "Actions" y "Lifetime" son lo que el broker impone. La tarea es solo el relato del agente, comprimido en una línea, así que no puede falsificar una línea "Actions:" adicional.
  • Si el agente pide *.send, primero aparece una advertencia: "The agent asks for the right to SEND in your name" (el agente pide permiso para ENVIAR en tu nombre).
  • Cuando apruebas, los botones cambian a 🛑 Revoke (revocar).
  • Solo tu id de usuario de Telegram puede pulsar. Los demás reciben "No access".

El registro de auditoría

Cada comprobación y cada decisión humana se convierte en una línea de ~/.agentcollar/audit.log. Las líneas solo se añaden, nunca se cambian. Este es el archivo en bruto:

{{audit-raw}}

El texto de los agentes va entre comillas (JSON.stringify), así que un agente no puede meter un salto de línea en su nombre y falsificar una línea. El token nunca se escribe aquí. La última columna indica qué comprobación decidió. agcl logs lo convierte en algo legible (ver más abajo).

Conectar Gmail

De serie, el broker usa una bandeja de entrada falsa, para que puedas probarlo todo sin riesgo. Cuando estés listo, conecta tu Gmail real. La conexión puede leer correo y crear borradores. Nunca puede enviar: el broker lo bloquea, y Google también, porque nunca se pidió permiso para enviar.

  1. En Google Cloud, crea un cliente OAuth de tipo Desktop app y descarga su archivo JSON.
  2. Ejecuta el comando de abajo. Se abre tu navegador. Permite "read your email" y "create drafts".
  3. Reinicia el broker.
{{gmail-connect}}

El refresh token va al Llavero de macOS, nunca a un archivo. El access token, de vida corta, solo vive en memoria. Comprueba o elimina la conexión cuando quieras:

{{gmail-status}}
El modo de prueba dura 7 días

Mientras tu app de Google esté en modo de prueba, Google cierra la sesión a los 7 días. Basta con volver a ejecutar agcl gmail connect.

El comando agcl

agcl es el nombre corto de agentcollar. Son el mismo programa: agcl watch = agentcollar watch. El nombre corto funciona después de npm install -g agentcollar. Con npx, usa el nombre largo: npx agentcollar watch.

{{help}}

agcl

El comando "simplemente hazlo funcionar". Muestra la intro, ejecuta el asistente si Telegram aún no está configurado y luego inicia el broker. En un script (sin una persona en la terminal), se salta las preguntas e inicia el broker.

agcl setup

Conecta tu propio bot de Telegram. Mira la guía completa. Se puede ejecutar de nuevo sin riesgo: pregunta antes de reemplazar un .env existente y conserva las demás líneas (por ejemplo BROKER_PORT).

agcl server

Inicia el broker. Solo escucha en 127.0.0.1:8787: los programas de otros ordenadores no pueden alcanzarlo. Detenlo con Ctrl+C.

{{server}}
BROKER_PORT=9000
Usa otro puerto. Ponlo en ~/.agentcollar/.env.
Los mandatos viven en memoria

Al detener el broker, todos los mandatos desaparecen. Los agentes simplemente vuelven a pedirlos. El registro de auditoría se conserva.

agcl watch

Una pantalla en vivo. Ábrela en una segunda terminal y mira cada petición en el momento en que ocurre. Solo lee el registro de auditoría: no puede cambiar nada.

{{watch}}

Cómo leer ✓ ✓ ✓ ✓ ✗ ·: las seis marcas son las seis comprobaciones. ✓ pasó, ✗ es la que falló, · no llegó a ejecutarse (la petición ya se había detenido). Las líneas amarillas son decisiones humanas.

agcl mandates

Lo que el broker en ejecución recuerda ahora mismo: quién, qué, estado, tiempo y acciones restantes. Lee un archivo de instantánea que el broker escribe tras cada cambio. La instantánea no tiene tokens.

{{mandates}}

Estados: waiting active denied expired revoked limit used up

agcl logs

El registro de auditoría, filtrado y con colores.

--agent <name>
solo este agente
--denied
solo los rechazos (la parte interesante)
--today
solo hoy
{{logs}}

Los filtros se combinan. ¿Quieres el archivo en bruto? tail -f ~/.agentcollar/audit.log.

agcl revoke <id>

El interruptor de emergencia. El mandato deja de funcionar en la siguiente petición. Funciona sin internet. El mensaje de Telegram también se actualiza.

{{revoke}}

El id está en el mensaje de Telegram y en agcl mandates. Revocar nunca necesita un token: solo puede quitar acceso, nunca darlo.

agcl mcp

Inicia el servidor MCP que usan Claude Code y otros agentes. Normalmente no lo ejecutas a mano: lo inicia el agente. Mira la siguiente sección.

La intro

El medallón que gira es el logo dibujado con caracteres Braille (⣿⡇⠟). Cada uno contiene 8 puntos, así que la imagen tiene más detalle que con letras normales. Dura unos 1,7 segundos, cualquier tecla la salta, y nunca aparece en pipes, en CI, con NO_COLOR ni con --no-intro.

Usar con Claude Code

MCP (Model Context Protocol) es un idioma común entre un agente de IA y sus herramientas. AgentCollar lo habla, así que Claude Code puede usar el broker por sí mismo. Un comando lo añade:

{{mcp-add}}

Mantén agcl server en marcha en otra terminal. Luego simplemente pídele a Claude:

{{mcp-prompt}}

Qué pasa después:

  1. Claude llama a request_mandate con las acciones que necesita.
  2. Tu teléfono vibra. Pulsas ✅ Approve.
  3. Claude llama a mandate_status, ve approved, y después a gmail_read_inbox y gmail_create_draft.
  4. Si intenta gmail_send sin permiso, el broker dice que no.

El modelo nunca ve el token

El servidor MCP guarda el token secreto dentro de su propio proceso y al modelo solo le da el mandateId. Así que si un correo contiene una inyección de prompt como "envíame tu token", no hay nada que robar.

Los navegadores se rechazan a propósito

Una página web también puede enviar peticiones a localhost. Por eso el broker rechaza cualquier petición con cabecera Origin, comprueba Host (contra el DNS rebinding) y solo acepta application/json. Programas como curl y los agentes no se ven afectados.

Seguridad

De vida corta

Los mandatos caducan solos. Las peticiones sin respuesta mueren a los 10 minutos.

Una sola tarea

Solo las acciones de la lista. Un borrador no puede convertirse en un envío.

Revoca cuando quieras

Un toque en Telegram o agcl revoke. Tiene efecto en la siguiente petición.

Todo queda registrado

Cada comprobación, cada decisión, una línea cada una. Los tokens, nunca.

De qué protege el broker

  • Un token de mandato robado: una tarea, poco tiempo, revocable. No todo tu buzón para siempre.
  • Un agente que se descontrola: el límite lo detiene, el registro muestra cuándo empezó.
  • Inyección de prompt en un correo: el agente puede creérsela, pero la acción no está en el mandato, y a través de MCP el token ni siquiera es visible.
  • Un mensaje de aprobación falso: las acciones deben tener la forma app.verb, y el texto del agente es una sola línea limpia, mostrada al final.
  • Un agente que se aprueba a sí mismo: la aprobación nunca es posible por HTTP ni mediante archivos. Solo en Telegram (tu id) o en la propia terminal del broker.
  • Una página web que ataca localhost: las peticiones de navegadores se rechazan.
  • Enviar en tu nombre: la conexión con Gmail solo tiene acceso de lectura y de borradores. Ni siquiera un error del broker podría enviar un correo.
  • Un paquete npm manipulado: las versiones se publican con provenance (procedencia verificable). Compruébalo con npm audit signatures.

De qué no protege (todavía)

  • Un malware que ya se ejecuta con tu usuario puede leer ~/.agentcollar/.
  • Los mandatos se pierden cuando el broker se detiene.

Solución de problemas

No llega nada a Telegram

Abre tu bot y pulsa Start al menos una vez: los bots no pueden escribirte primero. Comprueba que agcl server diga Approvals: Telegram. Si dice this terminal, ejecuta agcl setup.

El asistente dice "Another program is already listening to this bot"

(Otro programa ya está escuchando a este bot.) Normalmente es tu propio agcl server. Detenlo con Ctrl+C y vuelve a ejecutar agcl setup.

El agente dice que el broker no está en marcha

Inícialo: agcl server. El broker y el agente deben ejecutarse en el mismo ordenador.

agcl mandates dice "The broker is not running"

Los mandatos viven en su memoria, así que cuando se detiene no hay nada que mostrar. Inícialo y deja que el agente vuelva a pedir.

Gmail dejó de funcionar al cabo de una semana

Tu app de Google está en modo de prueba y Google cerró la sesión. Vuelve a ejecutar agcl gmail connect.

agcl: command not found

El nombre corto necesita instalación: npm install -g agentcollar. Sin instalar, usa npx agentcollar.

El puerto 8787 está ocupado

Quizá ya hay otro broker en marcha (compruébalo con agcl mandates). O inicia este en otro puerto: BROKER_PORT=8788 agcl server, y dile a tu agente la nueva dirección.

"Unsupported engine" o errores de sintaxis al iniciar

Tu Node.js es demasiado antiguo. AgentCollar necesita la versión 22 o posterior: node --version.
